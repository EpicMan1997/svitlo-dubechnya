# Наше Світло

Безкоштовний сімейний сайт/PWA з графіками відключень для чотирьох локацій. Джерела порівнюються між собою; достовірність графіка та давність останньої перевірки відображаються окремо. Це прогноз, а не вимір фактичної напруги.

**Актуальне оновлення:** спостерігаються запуски `workflow_dispatch` приблизно кожні 10 хвилин. Додано резервний GitHub `schedule` кожні 5 хвилин з 16:00 до 23:59 за Києвом, але GitHub може затримувати або пропускати такі події. Оновлення даних у відкритому PWA перевіряється кожні 15 секунд. Для стабільної затримки у 1–3 хвилини потрібен надійний зовнішній тригер з інтервалом 1–2 хвилини або окремий бекенд. [Налаштування зовнішнього планувальника](docs/RELIABLE-UPDATES.md).

## Публікація

Settings → Pages → Source → **GitHub Actions**. Потім Actions → **Наше Світло | оновлення графіків і публікація** → **Run workflow**. Адреса: https://EpicMan1997.github.io/svitlo-dubechnya/

## Тести

`pip install -r requirements.txt && python -m unittest discover -s tests -v`

## Встановлення як застосунку на iPhone

1. Відкрийте **Safari** → https://epicman1997.github.io/svitlo-dubechnya/
2. **Поділитися** → **На початковий екран**.
3. Увімкніть **Відкривати як вебзастосунок**, натисніть **Додати**.

Назва та іконка: «Наше Світло», жовта лампочка. Кожен член родини повторює ці кроки на власному iPhone. Жоден обліковий запис на сайті не потрібен.

- Застосунок має ту ж функціональність, що й сайт; окремий App Store чи платний Apple Developer акаунт не потрібний.
- При нестачі інтернету може відкриватися оболонка застосунку, але **дані про відключення ніколи не беруться з офлайн-кешу**.
- Робота у фоні та системні віджети потребують окремих налаштувань; PWA не гарантує фонові пуші.
- Прогнозні години не є підтвердженням фактичної напруги в будинку.

## Основний зовнішній планувальник

[**Покрокове налаштування для нашого репозиторію**](docs/RELIABLE-UPDATES.md)


GitHub `schedule` є резервним і може пропускати запуски. Зовнішній cron-job.org можна налаштувати відправляти `POST` з `{"ref":"main"}` кожні 1–2 хвилини (за потреби швидкого виявлення нового графіка; враховуйте навантаження) на

`https://api.github.com/repos/EpicMan1997/svitlo-dubechnya/actions/workflows/refresh.yml/dispatches`

з окремим fine-grained GitHub token **лише для цього репозиторію**, з правом **Actions: Read and write**. Токен необхідно зберігати тільки в приватних HTTP-заголовках завдання планувальника: `Authorization: Bearer TOKEN`, `Accept: application/vnd.github+json`, `Content-Type: application/json`. **Не вставляйте токен у код сайту, репозиторій, URL або чат.**

При зовнішньому планувальнику залишіть внутрішній GitHub `schedule` вимкненим, щоб запуски не дублювалися і не скасовували один одного.

## Раннє виявлення графіка на завтра

- Для всіх чотирьох локацій нові графіки беруться тільки з джерел, які підтвердили **дату та групу**.
- Якщо вже є одна коректна версія, але немає незалежного збігу, сайт показує жовтий статус **«Попередній графік»**, джерело, інтервали та суперечності. Він не видається за підтверджений.
- Коли збігаються принаймні два незалежні джерела, статус переходить у **«За графіком»**.
- Індикатор «Завтра» і список локацій позначають нові дані для кожної локації, доки їх не відкрили.
- Збирач запитує незалежні сайти паралельно; клієнт повторно отримує `data.json` кожні 15 секунд. Без відкритого сайту фонових push-сповіщень немає.
- Для гарантованого майже миттєвого виявлення без черг GitHub Actions потрібні зовнішній бекенд і система push-сповіщень; GitHub Pages + GitHub Actions не надають hard real-time гарантій.
